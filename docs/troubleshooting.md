# Troubleshooting

Failures whose symptom points somewhere other than the cause. Every entry here
cost real time to diagnose at least once.

Organised by **what you see**, not by what is wrong — because when you need this
page you do not yet know what is wrong.

---

## Setup and install

### `npx expo install` vs `npm install`

Always install native and Expo packages with `npx expo install`. Plain
`npm install` resolves the newest version rather than the one matching the SDK,
and the result compiles and then misbehaves on device. `npm run doctor` checks
for this.

### CocoaPods fails with `Encoding::CompatibilityError`

> `Unicode Normalization not appropriate for ASCII-8BIT`

CocoaPods needs a UTF-8 locale and a non-interactive shell often has none.
`npm run ios` sets `LANG` and `LC_ALL` for exactly this reason. If you invoke
`pod install` yourself:

```bash
LANG=en_US.UTF-8 LC_ALL=en_US.UTF-8 pod install
```

### `xcodebuild` offers no simulator destinations at all

Not with a booted simulator, not with `generic/platform=iOS Simulator`, not with
`-sdk iphonesimulator` — while `xcodebuild -showsdks` cheerfully lists
`iphonesimulator26.5` the whole time.

Xcode's **iOS Simulator platform ships separately from the SDK**, and when it is
missing every destination-based diagnostic returns empty rather than explaining
itself. One command fixes it, needs no password, and downloads 8.52 GB:

```bash
xcodebuild -downloadPlatform iOS
```

On a nearly-full disk, free space first: `xcrun simctl runtime list` and
`xcrun simctl runtime delete <id>` remove an old runtime you can re-download.

## Building

### `mergeDexRelease` fails with an empty error message

> `DexArchiveMergerException: Error while merging dex archives:`

…and nothing after the colon. The real cause is about forty lines further down
the log: `java.lang.OutOfMemoryError: Java heap space`, inside R8.

Expo's template sets `org.gradle.jvmargs=-Xmx2048m`, which is not enough to merge
this app's five dex files. Editing `android/gradle.properties` is pointless — it
is regenerated by every prebuild and `android/` is gitignored. Pass it instead:

```bash
./gradlew assembleRelease -Dorg.gradle.jvmargs="-Xmx6g -XX:MaxMetaspaceSize=1g"
```

EAS's builders do not hit this.

### The app is running screens from a previous phase

A development build **silently falls back to a stale cached bundle when Metro is
unreachable**. It keeps running and shows whatever was built last — during Phase
13 it served Phase 10 screens while looking entirely current.

The tell is a `Cannot connect to Expo CLI` toast. **Discard anything you observed
after seeing it.** Reconnect:

```bash
adb reverse tcp:8081 tcp:8081
```

### A config-plugin change has no effect, or the wrong one

Expo runs mods in **reverse registration order**. `withMod` wraps the
previously-registered mod and each action runs _before_ chaining down to it, so
the last plugin listed runs first and the first plugin listed runs last.
Autolinked plugins are registered after everything in the `plugins` array, so
they run before all of it.

This is why `plugins/withoutUnusedCapabilities.ts` is listed **first** in
`app.config.ts` despite needing to run last. It looks like a mistake. It is not.

## The map and location

### The Android map is completely blank

Not just missing tiles — markers and radius circles too, so the screen looks
broken rather than unstyled.

Android has no non-Google map provider, and a development or release build needs
its own key. Set `EXPO_PUBLIC_GOOGLE_MAPS_API_KEY_ANDROID` in `apps/mobile/.env`
and rebuild. Expo Go supplies its own key, which is why the map works there and
not in your build.

**iOS is unaffected** — it uses Apple Maps and needs no key.

The data layer keeps working regardless: the header still counts nearby spots and
proximity warnings still fire. If you are debugging the _data_ and not the map,
you can ignore this.

### The iOS simulator is in San Francisco again

It resets on boot. Worse, it **ignores a `simctl location set` issued before the
app has resolved its first fix** — so the obvious sequence of setting the
location and then launching does not work.

Seed the location where the simulator actually is, then force a refetch from the
app's own locate control.

### Android falls back to low accuracy and never prompts

The Play Services "Location Accuracy" dialog is suppressed deliberately
(`mayShowUserSettingsDialog: false`), and the app falls back to low accuracy on
`ERR_LOCATION_SETTINGS_UNSATISFIED` rather than nagging. Enable high-accuracy
location in the emulator's own settings if you need it.

## Firestore and the emulators

### Everything returns an empty list and nothing errors

**`getDocs` does not throw when offline.** It resolves from its own empty local
cache and returns `[]`, which is indistinguishable from "there is nothing here".

Every repository in this project checks `snapshot.metadata.fromCache` and throws a
network error instead. **Preserve that check.** Without it, "no signal" renders as
"no black spots nearby" — the single most dangerous failure mode this app has.

### `connectFirestoreEmulator` throws after a Fast Refresh

> `Firestore has already been started`

Emulator settings are supplied to `initializeFirestore` at creation rather than
being connected afterwards, and connection state is tracked **per service**.
If you add a new Firebase service, follow the same pattern.

### Every write fails with an opaque `PERMISSION_DENIED`

Check whether a Firestore converter's `toFirestore` is touching the data on its
way out. **It runs on the data being written**, and an early version of this
project's converter stripped `serverTimestamp()` sentinels — so the rules, which
require a server timestamp, were handed nothing and refused everything.

### The emulator logs "evaluation error at L…" for something obviously allowed

That message appears for **ordinary denials and for genuine rule errors alike**,
which is how Phase 13's bug hid for eleven phases.

If a rule denies something it plainly should allow, read the full message for
**`Function not found`**. An erroring rule is a denial, so a typo in a helper
function silently forbids the operation it was meant to permit.

### The emulators refuse to start on a Java version error

> `firebase-tools no longer supports Java version before 21. Please install a JDK at
version 21 or above to get a compatible runtime.`

`firebase-tools` 15 dropped Java 17. The emulators exit immediately, so it reads as
"emulators broken" rather than "wrong JDK".

`java -version` to check. The CI workflow pins Temurin 21 in the `emulator-suites` job
for this reason — it was pinned to 17 on the first push and failed exactly here, which
is the only thing the first CI run caught.

### Rules tests fail in confusing ways when run in parallel

`node --test` runs files in parallel by default. The rules suite runs with
`--test-concurrency=1`, and that is **load-bearing**: every file shares one
emulator and `clearFirestore()` wipes everything. Do not remove it.

### `env.clearStorage()` does not empty the bucket

It does not clear the bucket the rules-test contexts actually write to.
`firebase/tests/storage.test.mjs` derives its uids from the clock so every run
uses fresh paths.

### Overwriting a Storage object is not an `update`

It is evaluated as a **`create`**. `allow update: if false` alone does not
prevent an overwrite — requiring `resource == null` on create is what does.

### Account deletion reports success but deletes no photographs

The Admin SDK's default bucket is `<project>.appspot.com`, but this project's
bucket is `<project>.firebasestorage.app`. Both are valid names, so the SDK
returns an **empty bucket** rather than erroring.

See `bucketName()` in `functions/src/firebaseAdmin.ts`. Only the end-to-end test
caught this.

### `sweepOrphanedImages` never runs locally

It needs the Pub/Sub emulator, which `npm run emulators` does not start; the
emulator logs `function ignored`. Its decision logic is pure and unit-tested, but
the scheduled trigger itself is verified only by inspection.

## The dashboard

### `FlatCompat` throws "Converting circular structure to JSON"

`eslint-config-next` 16 ships native flat configs. Spread
`eslint-config-next/core-web-vitals` directly instead of wrapping it.

### `next build` fails with no `.env.local`

The build evaluates server modules during page-data collection, and
`src/lib/env.ts` refuses to start unconfigured. Copy the template:

```bash
cp apps/admin/.env.local.example apps/admin/.env.local
```

CI does the same thing, for the same reason.

### `next-env.d.ts` keeps showing as modified

Next rewrites it between the dev and production type paths, so `next dev` and
`next build` each flip it. It is tracked, and it is churn; nothing is wrong.

### A server action cannot be driven with `curl`

Next 16 does not expose server-action ids in the HTML. Drive them through the
browser, or test the logic they call directly — which is what the test suite
does.

## The analytics service

### `/analyse` returns 401 with a token that looks right

The service **fails closed**: with no `ANALYSIS_API_TOKEN` configured it refuses
every request rather than allowing all of them. If you have not created the
service's configuration, that is the cause:

```bash
cp services/analytics/.env.example services/analytics/.env
```

Restart the service afterwards — settings are read once and cached.

### A site does not cluster, and nothing says why

DBSCAN's neighbourhood is 150 m and it needs 3 points. Reports placed by bearing
and offset are further apart than they look: at a 1800 m offset, one degree of
bearing is about 31 m, so a 6-degree step puts consecutive reports 188 m apart —
outside the neighbourhood. The site then silently does not exist.

That is exactly what the first version of `seedIncidentReports.mjs` did.

### `firebase_admin.credentials` has no anonymous option

There is no "no credentials" credential for emulator use. See
`_EmulatorCredentials` in `services/analytics/app/repositories/firestore.py`.

## Tests and tooling

### A test passes but the assertion never ran

RNTL 14 made `render` and `fireEvent` **async**. A missing `await` typechecks
cleanly and fails at runtime — or worse, passes vacuously.

### The React Compiler ESLint rules reject something that looks fine

They are strict, and they have caught real bugs here. No `setState` in an effect
for derived state, no writing refs during render, and **no `Date.now()` during
render** — that last one is why `src/utils/useNow.ts` exists.

### A Zod schema's time-based validation is stuck

**A schema that closes over `Date.now()` freezes the clock at module load.**
`buildIncidentReportFormSchema` takes a clock _function_, read inside each
refinement, for this reason.

### `expo-notifications` throws at import time on Android under Expo Go

`import * as Notifications from 'expo-notifications'` fails at import. The app
loads it lazily behind a `try`/`catch` `require` in `alertDelivery.ts`, kept
permanently because the module is also reached from a headless background task.

### `plutil -extract` mangles the file

It **writes back to the file** unless given `-o -`. Grep the raw XML instead.

### `adb shell input text` types the wrong thing

It splits on spaces — use `%s`. And validation errors move the layout, so
coordinates captured from an earlier screenshot land on the wrong control. The
iOS simulator has neither problem.

## Things that are not bugs

- **The iOS back button on a pushed screen reads `(tabs)`.** Expo Router uses the
  route-group directory name as the back title. Cosmetic, iOS-only.
- **`getReactNativePersistence` is missing from `firebase@12`'s types.** Worked
  around in `apps/mobile/types/firebase-auth-rn.d.ts`. Auth persistence is
  SecureStore-backed with chunking — SecureStore keys must match `/^[\w.-]+$/`,
  and Android caps values near 2 KB.
- **A marker tap also fires `MapView.onPress`.** Guard on
  `event.nativeEvent.action !== 'marker-press'`.
- **`npm audit` reports around 46 advisories.** All transitive dev tooling,
  absent from the shipped bundle, not fixable without breaking the Expo
  toolchain.
- **The seeded "UNVERIFIED" and "INACTIVE" black spots do not appear in the
  app.** That is what they are for.
